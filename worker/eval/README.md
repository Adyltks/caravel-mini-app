# Проверка бота-продавца на разыгранных клиентах

15 вымышленных клиентов (`personas.json`) переписываются с ботом. Клиента играет Claude Sonnet 5.5,
диалог оценивают код (`checks.mjs`) и судья Claude Opus 5.5 по рубрике (`rubric.md`).
Бот вызывается через `botReply` из `../src/bot/brain.js`, хранилище берётся из `../src/bot/store.js`.

**Живой прогон тратит деньги API. Запускать только с согласия владельцев.**

## Без денег (можно всегда)

В PowerShell, в папке `C:\PROJECTS\caravel-mini-app\worker`:

```powershell
node --test eval/checks.test.mjs   # тесты проверок, 12 штук
node eval/run.mjs --dry            # проверка запускателя: бот, клиент и судья заменены заглушками
```

Режиму `--dry` не нужны ни ключ, ни `brain.js`. Результат пишется в `eval/results/<дата>-dry.json`.
В `--dry` у `jewelry-pay-now-night` будет «ПРОВАЛ» (M2): заглушка бота не понимает нишу из текста
и называет обычную цену «Магазин» вместо цены для ювелирки. Так и задумано: видно, что проверка цен работает.

База знаний (`aduka.md`, `rules.md`) ищется сама: `worker/src/knowledge`, `worker/src/bot/knowledge`,
затем соседний репозиторий `C:\PROJECTS\catalog-instagram-ads\bot\knowledge`.
Другая папка - через переменную `ADUKA_KNOWLEDGE_DIR`.

## Живой прогон

1. Убедиться, что `worker/src/bot/brain.js` и `store.js` готовы и `node eval/run.mjs --dry` проходит.
2. Открыть PowerShell в `C:\PROJECTS\caravel-mini-app\worker` и ввести ключ только в это окно (в файлы и чат не вставлять):
   ```powershell
   $s = Read-Host "Ключ Anthropic" -AsSecureString
   $env:ANTHROPIC_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
   ```
3. Сначала один клиент (оценка: $0.3-0.7):
   ```powershell
   node eval/run.mjs --persona cosmetics-ideal-day --max-cost 1
   ```
4. Полный прогон, если первый прошёл нормально:
   ```powershell
   node eval/run.mjs --max-cost 8
   ```
5. Закрыть окно PowerShell или удалить ключ: `Remove-Item Env:ANTHROPIC_API_KEY`.

Флаги:
- `--persona id[,id]` - только эти клиенты (id - в `personas.json`);
- `--max-cost N` - остановиться, когда расход превысит N долларов (по умолчанию 3). Проверка идёт перед каждым запросом,
  поэтому перерасход - не больше одного ответа. Оставшиеся клиенты помечаются «пропущен»;
- `--turns N` - сколько реплик клиента максимум (по умолчанию 12);
- `--no-judge` - без судьи (дешевле, только проверки кодом);
- `--dry` - без сети.

Прогон не трогает дневной лимит бота в D1: для каждого клиента своё хранилище в памяти.
Бот получает `env = { DAILY_BUDGET_USD: "3", BOT_EFFORT: "low" }` и время клиента: день 14:00, ночь 23:30 по Бишкеку.

## Сколько стоит полный прогон (оценка)

Цены: Opus 5.5 $4 / $20, Sonnet 5.5 $2 / $10 за 1 млн токенов ввода / вывода; чтение кэша 0.1x, запись 1.25x
(справочник Claude API на 2026-10-24, перепроверить перед прогоном).

| Часть | Как считали | На одного клиента | 15 клиентов |
|---|---|---|---|
| Бот, Opus 5.5 low | ~10 запросов; правила и база ~11 тыс. токенов из кэша, история ~1.5 тыс., ответ с мышлением ~300-600 | $0.2-0.3 | $3-4.5 |
| Клиент, Sonnet 5.5 low | ~9 запросов по ~2 тыс. токенов ввода и ~300 вывода | ~$0.07 | ~$1 |
| Судья, Opus 5.5 medium | рубрика и база ~10 тыс. токенов (кэш), диалог ~4 тыс., ответ с мышлением 1.5-4 тыс. | $0.05-0.1 | $0.8-1.5 |
| **Итого** | | | **около $5-7** |

Это оценка, а не замер. Если `brain.js` не кэширует правила и базу, бот подорожает примерно вдвое,
и полный прогон выйдет до $10. Точная сумма после прогона - в `summary.costUsd` файла результатов.
Расход бота берётся из его `costUsd`, клиента и судьи - из `usage` ответов API.

## Результаты

`eval/results/<дата>.json` (в git не попадает, см. `.gitignore`): для каждого клиента диалог, вызовы `create_lead` и `handoff`,
нарушения кода с цитатой (`evidence`), вердикт судьи, стоимость. В консоли - строка на клиента и итог:
сколько дошло до заявки, сколько провалов, нарушения по критериям, расход.

Как читать: «ПРОВАЛ» = есть обязательное нарушение (M1-M9) у кода или `fail` судьи по M-критерию.
Сначала смотреть `evidence`: регулярка может ошибиться. Ложное срабатывание - поправить `checks.mjs`
и добавить пример в `checks.test.mjs`.

## Что сверить с `tools.js`

Имена полей `create_lead` в проверках принимаются с синонимами (`LEAD_FIELDS` в `checks.mjs`):
`niche`, `name`, `contact`, `pain`, `current_channel`, `positions`, `tariff`, `meeting`, `temperature`.
Если в схеме инструмента другие имена - добавить их в `LEAD_FIELDS`.
